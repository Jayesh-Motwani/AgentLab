Code documentation
==================

Purpose
-------
Documenting the code that currently exists in this repository. The following lists implemented modules, their responsibilities, available API endpoints, and run instructions.

Implemented modules
-------------------
- backend/src/main.py
  - Creates FastAPI app, registers the chat router at /api/chat, and runs an async lifespan that calls init_db().
  - Exposes GET / which returns a simple JSON greeting and the MY_PROJECT_NAME environment value.

- backend/src/api/db.py
  - Creates an SQLModel engine using a DATABASE_URL value defined in the file.
  - init_db() runs SQLModel.metadata.create_all(engine).
  - get_session() yields a SQLModel Session for dependency injection.
  - Note: DATABASE_URL is set to a placeholder string in the current code.

- backend/src/api/chat/models.py
  - ChatMessagePayload: request schema with a single "message" field.
  - ChatMessage: SQLModel table with id, message, created_at.
  - ChatMessageResponseList: response schema used by the recent messages endpoint.

- backend/src/api/chat/router.py
  - Router mounted at /api/chat.
  - GET /api/chat/ returns {"status": "ok"}.
  - GET /api/chat/recent/ returns up to 10 recent ChatMessage records from the DB.
  - POST /api/chat/ accepts {"message": "..."}, stores it in the DB, and returns an EmailMessage produced by the LLM service.

- backend/src/api/ai/schemas.py
  - EmailMessage Pydantic model with fields: subject (str), contents (str), invalid_request (optional bool).

- backend/src/api/ai/llms.py
  - Builds a langchain_openai.ChatOpenAI client from environment variables: OPENAI_MODEL_NAME (required), OPENAI_API_KEY (required), OPENAI_BASE_URL (optional).
  - Raises NotImplementedError when OPENAI_API_KEY is missing.

- backend/src/api/ai/services.py
  - generate_email_message(query: str) -> EmailMessage: uses the ChatOpenAI client with structured output to generate a plain-text email representation.

Deployment / run (current)
--------------------------
- docker-compose.yaml defines two services:
  - backend: builds from ./backend, maps host 8080 -> container 8000 and runs uvicorn main:app --host 0.0.0.0 --port 8000 --reload
  - db_service: postgres:17.5, exposes 5432 and mounts a named volume managed_db_data

- To run locally with Docker from the repository root:
  docker-compose up --build

Environment variables used by current code
------------------------------------------
- MY_PROJECT_NAME: returned by GET / (main.py)
- API_KEY: read by main.py (example only)
- OPENAI_API_KEY: required by backend/src/api/ai/llms.py
- OPENAI_MODEL_NAME: required by llms.py
- OPENAI_BASE_URL: optional

API endpoints (implemented)
---------------------------
- GET /
  - Returns: {"Hello": "World AGAIN!", "project_name": <MY_PROJECT_NAME>}

- GET /api/chat/
  - Returns: {"status":"ok"}

- GET /api/chat/recent/
  - Returns: List[ChatMessageResponseList] with recent messages (up to 10)

- POST /api/chat/
  - Body: {"message": "..."}
  - Action: stores message in DB and returns EmailMessage generated by the LLM service

Notes and next steps
--------------------
- DATABASE_URL is currently hard-coded in backend/src/api/db.py; consider switching to an environment variable for production use.
- The LLM client requires valid OPENAI_API_KEY and OPENAI_MODEL_NAME. If not provided, the app will raise an error at import time.
- Add more robust error handling, logging, and tests as development continues.
